# EzEizo — דפי תקלות משותפים

גרסה: **1.2.0**

האפליקציות מתארחות ב־GitHub Pages: `/Metis/` למנהל ו־`/mechanic/` לטכנאי. Firebase Authentication משמש לכניסה ו־Cloud Firestore מסנכרן תקלות בזמן אמת. כל תקלה משויכת לטכנאי אחד לפי UID. רק הטכנאי המשויך רואה את התקלה. פתיחת תקלה מחייבת תיאור תקלה, אישור תדריך בטיחות וחתימת משלח המשימה. הגשת הטכנאי מחייבת תיאור תיקון, 12 הכרעות בפעולות (פעולה 11 מאפשרת ✓ או X), שעת הגעה בפעולה 2, שעת סיום בפעולה 12, מילוי מלא של החלקים שנבחרו וחתימות בטיחות וסיום. הדף עובר ל״תקלות לסגירה״ ורק חתימת בודק הדף מעבירה אותו ל״תקלות סגורות״. המנהל יכול להחזיר דף לטכנאי לעריכה ולסנן תקלות סגורות לפי טכנאי. הטיוטה נשמרת במכשיר הטכנאי עד להגשה בענן.

בטופס המנהל בוחרים טייסת, דת״ק ומטוס מתוך רשימות עם חיפוש; הדת״קים והמטוסים תלויים בטייסת. בחירת שם מערכת ממלאת קוד, בחירת מטוס ממלאת את חליפת הל״א גרניט, והקבועים נפתחים לעריכה לפי הצורך. הקלדה ללא בחירת תוצאה לא מאפשרת לפתוח תקלה.

## השלמת הגדרה חד־פעמית ב־Firebase Console

1. Authentication → Users → Add user: צור את חשבון המנהל עם הדוא״ל `roisuissa6@gmail.com` וסיסמה שתבחר עכשיו (מומלץ להחליף סיסמה שנשלחה בצ'אט). אל תכניס סיסמה לקוד או ל־repo. אם החשבון כבר קיים, אין צורך ליצור אותו שוב.
2. Firestore Database → Rules: החלף את כל הכללים בתוכן הקובץ [`firestore.rules`](firestore.rules) ולחץ Publish. כניסה מוצלחת של החשבון הזה תיצור אוטומטית את מסמך ההרשאה `roles/{UID}` עם השם נימר. אין צורך להעתיק UID או ליצור מסמך מנהל ידנית.
3. אם הכניסה מדווחת על דומיין לא מורשה, Authentication → Settings → Authorized domains: הוסף `cartonush.github.io`.
4. פתח `/Metis/`, התחבר כמנהל ועבור לדף **ניהול משתמשים**. צור לפחות שני טכנאים בשם ובכתובת שתבחר; טכנאים מתחברים ב־`/mechanic/`.
5. תקלה מקומית ישנה מהמכשיר שבו נוצרה תיובא אוטומטית אחרי כניסת המנהל כתקלה לא משויכת. עבור ל**תקלות פתוחות** ושייך אותה לטכנאי כדי שתופיע אצלו. אל תמחק את נתוני אפליקציית המנהל לפני הייבוא.

**הסרת משתמש:** כפתור "מחק משתמש" מסיר אותו מרשימת הפעילים וחוסם את גישתו ב־Firestore. ההיסטוריה והמספרים הסידוריים שלו נשמרים, ואפשר לשחזר אותו מרשימת המשתמשים שהוסרו. לפני הסרה צריך לשייך מחדש תקלות פתוחות. ברשימת המשתמשים שהוסרו, כפתור "מחק סופית" קורא לפונקציית Firebase שמאמתת את המנהל ומוחקת את חשבון Firebase Authentication של המשתמש. רשומת זיהוי מינימלית נשמרת רק כדי לסנן היסטוריית תקלות; היא מוסתרת מרשימת המשתמשים. הפונקציה דורשת פריסה חד־פעמית כמתואר להלן. עצם יצירת חשבון Auth באמצעות ה־SDK היא ציבורית כשהספק Email/Password פעיל, אולם רק המנהל יכול ליצור עבורו מסמך הרשאת טכנאי ב־Firestore.

## פריסת שינויי Firebase

את האתר ב־GitHub Pages אפשר לפרסם בנפרד, אך מחיקה סופית והזרימה החדשה של החזרת דף, הגשה לבודק וסגירה דורשות פרסום הפונקציה וכללי Firestore החדשים בפרויקט `ezeizo`. ממחשב עם גישת מנהל לפרויקט, הרץ משורש ה־repo:

```sh
npm --prefix functions install
npx firebase-tools login
npx firebase-tools deploy --only functions,firestore:rules --project ezeizo
```

אפשר לפרסם את `firestore.rules` גם דרך Firebase Console → Firestore Database → Rules. אין לשמור פרטי התחברות או מפתח Admin ב־repo. לפריסת Cloud Functions ייתכן צורך בהפעלת חיוב בפרויקט Firebase.

ה־web API key בקוד מזהה את פרויקט Firebase ואינו סיסמה. המערכת היא המחשה עם נתונים מומצאים. אין להזין מידע מסווג או פרטים מבצעיים.

מגרסה 1.11.0 מנהל בוחר לפחות שני טכנאים לתקלה; כל טכנאי מקבל עותק עצמאי באותו מספר סידורי, כך שהוא ממלא וחותם על הדף שלו. הערות המנהל מוצגות לקריאה, וטכנאי יכול להוסיף הערות בלי אפשרות מחיקה בממשק.

בגרסה 1.12.0 שיוך הטכנאים נעשה בשתי רשימות בחירה לפחות. לחצן ״הוסף טכנאי״ מוסיף רשימה נוספת; אין אפשרות לשייך פעמיים את אותו טכנאי.

בגרסה 1.13.0 הוסרה הטייסת ״מוסכים״. בכל טייסת אפשר לבחור דת״ק ״מוסך״ ואז מוסך א, מוסך ב או כנפ״ת. שורת שמות הטכנאים הוסרה מפרטי התקלה, וחליפת הל״א ניתנת לבחירה מתוך גרניט, אימפריה אקטיבית ואימפריה פאסיבית.

בגרסה 1.14.0 הבחירה ברשימות מתבצעת בסיום הלחיצה, ללא שינוי מיקוד לשדה אחר. חליפת הל״א מציגה רק את שלוש האפשרויות. נוספו כפתורי חזרה למנהל ולדף התקלה של הטכנאי. כפתור יצירת משתמשי הדוגמה הוסר ונוספה הסרת גישה למשתמש פעיל, עם אפשרות שחזור.

בגרסה 1.15.0 ארבעת כפתורי הניווט הראשיים של המנהל מוצגים בסרגל קבוע בתחתית המסך עם ריווח לתוכן ולכפתורי הפעולה.

בגרסה 1.16.0 כפתור ההתנתקות של המנהל נמצא בצד שמאל בשורת הבקרה, וכפתור החזרה מוסתר בכל ארבעת המסכים הראשיים.

בגרסה 1.17.0 ניתן למחוק חשבון טכנאי סופית לאחר שהוסר, בכפוף לפריסת הפונקציה. דף תקלה סגורה במנהל הציג את כל טופס הטכנאי בקריאה בלבד, עם זמני פתיחה וסגירה בתחילתו. אפשרות העריכה הישירה של המנהל מגרסה זו הוחלפה בגרסה 1.1.9 בהחזרה לטכנאי. פעולות 2 ו־12 מחייבות בחירת שעה.

בגרסה 1.1.8 שדה חליפת ל״א בטופס המנהל מוצג ונפתח לעריכה רק אחרי בחירת מטוס מתוך הרשימה. מספור הגרסה בתצוגה עודכן ל־1.1.8.

בגרסה 1.1.9 מנהל יכול להחזיר דף סגור לטכנאי לעריכה, תוך שמירת פרטי הסגירה הקודמים ותיעוד ההחזרה. פתיחת תקלה מחייבת אישור פרטים וטכנאי אחד לפחות, עם שתי משבצות בחירה כברירת מחדל. טכנאי רואה את הערות המנהל והערותיו באותה תיבה, יכול להוסיף אחרי הערות המנהל, בוחר יחידות מתוך MLPRF, PSP, DMT, ויכול למלא ביקורת כניסה. בביקורות הכלים השדה של הבודק הוא מספר אישי. הכניסה אינה מהבהבת במעבר בין דפים כשההתחברות קיימת. יש לפרסם את כללי Firestore המעודכנים לפני שימוש בהחזרה לטכנאי.

בגרסה 1.1.10 מסכי המנהל והטכנאי מציגים שלד טעינה מונפש בזמן שחזור הכניסה וטעינת הטופס. המנהל מאשר תדריך בטיחות וניהול סיכונים וחותם כמשלח המשימה לפני פתיחת תקלה; חתימתו מוצגת לטכנאי. הטכנאי חותם בתחילת הטופס על בדיקת בטיחות המטוס ובסופו על הצהרת שלמות הנתונים. החתימה האחרונה מעבירה את התקלה למצב ממתין לבדיקת בודק הדף. תחת תקלות סגורות במנהל נוסף מסך ״תקלות לסגירה״; חתימת בודק הדף בו מסיימת את הסגירה. יש לפרסם את כללי Firestore החדשים להפעלת הזרימה.

בגרסה 1.2.0 הותאם מספור הגרסה בתצוגות ובמטמון ה־PWA. העדכון הבא ימוספר 1.2.1.
