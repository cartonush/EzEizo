# EzEizo — ניהול דפי תקלות (הדגמת GitHub)

גרסה: **1.6.0**

- `/Metis/` — המנהל פותח תקלות ב־`data/issues.json` בענף `main`. מספר סידורי בן שש ספרות נקבע על סמך הקובץ המשותף. הטייסת והדת״ק נפרדים, 12 הפעולות קבועות, ויש דפים לפתיחה, פתוחות וסגורות.
- `/mechanic/` — קורא תקלות פתוחות ישירות מ־GitHub. הטכנאי ממלא טיוטה מקומית וסוגר תקלה ב־`main` רק לאחר השלמת כל הפעולות ושעת הסיום. המנהל רואה את הסגירה לאחר רענון.

קריאה מה־repo הציבורי אינה דורשת הרשאה. פתיחה וסגירה מחייבות fine-grained personal access token של GitHub, מוגבל ל־`cartonush/EzEizo` עם הרשאת `Contents: Read and write`. מזינים את ההרשאה בכל אפליקציה שצריכה לכתוב; היא נשמרת ב־`sessionStorage` של אותה אפליקציה, אינה נכתבת ל־repo ואינה נכללת בקבצי האתר. בעת חיבור ההרשאה במנהל, תקלות ישנות מ־`localStorage` שאינן ב־GitHub מועלות לקובץ המשותף, כולל מספרן המקורי כשהוא פנוי.

זהו אב־טיפוס עם GitHub כאחסון. כל כתיבה יוצרת commit ל־`main`; קובץ התקלות פומבי ומוגבל בגודלו על ידי GitHub Contents API. ההרשאה מאפשרת שינוי תוכן ה־repo כולו, לא רק קובץ הנתונים. אין כאן הרשאות נפרדות למנהל ולטכנאי או סנכרון טיוטות תוך כדי מילוי. אין להזין נתונים מבצעיים או רגישים.

להרצה מקומית: `python -m http.server 8000`, ואז לפתוח `/Metis/` ו־`/mechanic/`.
