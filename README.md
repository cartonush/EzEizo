# EzEizo — דפי תקלות משותפים

גרסה: **1.7.0**

האפליקציות מתארחות ב־GitHub Pages: `/Metis/` למנהל ו־`/mechanic/` לטכנאי. Firebase Authentication משמש לכניסה ו־Cloud Firestore מסנכרן תקלות בזמן אמת. פתיחת תקלה מייצרת מספר סידורי בן שש ספרות, והתקלה מופיעה מיד ברשימת הטכנאי. סגירתה מחייבת את 12 הפעולות ושעת סיום; הדף הסגור מוצג במנהל. טיוטת טיפול נשמרת מקומית עד לסגירה מוצלחת בענן.

## השלמת הגדרה ב־Firebase Console

1. Authentication → Users → Add user: צור חשבון מנהל וחשבון טכנאי עם כתובות דואר וסיסמאות שונות. אל תשתף סיסמאות בצ'אט או ב־repo.
2. לכל משתמש העתק את ה־User UID המוצג בטבלת המשתמשים.
3. Firestore Database → Data: צור collection בשם `roles`. צור מסמך עם Document ID זהה ל־UID של המנהל, שדה `role` מסוג string וערך `manager`. צור מסמך נוסף עם UID הטכנאי, שדה `role` מסוג string וערך `technician`.
4. Firestore Database → Rules: החלף את כל הכללים בתוכן הקובץ [`firestore.rules`](firestore.rules) ולחץ Publish. רק אחרי הפרסום החשבונות יוכלו לקרוא ולכתוב תקלות.
5. אם הכניסה מדווחת על דומיין לא מורשה, Authentication → Settings → Authorized domains: הוסף `cartonush.github.io`.
6. פתח את שתי האפליקציות, התחבר בחשבון המתאים, פתח תקלה במנהל ובדוק שהיא מופיעה בטכנאי. התקלה הקיימת באפליקציית המנהל מהמכשיר שבו נוצרה מיובאת אוטומטית אחרי כניסת המנהל; אין צורך בהעברה ידנית. אל תמחק את האפליקציה/נתוני האתר לפני הייבוא.

הכללים מאפשרים יצירת תקלות למנהל בלבד, סגירת תקלה פתוחה לטכנאי בלבד וקריאה למשתמשים בעלי תפקיד. אין ממשק לרישום משתמשים או לשינוי תפקידים. ה־web API key בקוד מזהה את פרויקט Firebase ואינו סיסמה; האבטחה תלויה בכללי Firestore ובגישה לחשבונות.

המערכת היא המחשה עם נתונים מומצאים. אין להזין מידע מסווג או פרטים מבצעיים.
