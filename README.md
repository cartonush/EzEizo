**נדרש לפרסם את `firestore.rules` החדשים בפרויקט Firebase `ezeizo` לפני שימוש בסגירת טופס מודפס.** עצם מיזוג הקוד ב־GitHub אינו מפרסם את כללי Firestore. יש לפרסם אותם דרך Firebase Console → Firestore Database → Rules, או באמצעות `npx firebase-tools deploy --only firestore:rules --project ezeizo` מחשבון מורשה.

## השלמת הגדרה חד־פעמית ב־Firebase Console

1. Authentication → Users → Add user: צור את חשבון המטיס עם כתובת דוא״ל שבחרת וסיסמה חדשה. אל תכניס פרטי התחברות לקוד או ל־repo. אם החשבון כבר קיים, אין צורך ליצור אותו שוב.
2. ודא שב־Firestore קיים מסמך `roles/{UID}` של חשבון המטיס עם `role: "manager"` ו־`active: true`. לחשבון מטיס שכבר עבד באתר המסמך אמור להיות קיים. התקנה חדשה דורשת יצירת המסמך ידנית דרך Firebase Console לאחר מציאת ה־UID ב־Authentication. לאחר מכן פרסם את הקובץ [`firestore.rules`](firestore.rules) דרך Firestore Database → Rules.
3. אם הכניסה מדווחת על דומיין לא מורשה, Authentication → Settings → Authorized domains: הוסף `cartonush.github.io`.
4. פתח `/Metis/`, התחבר כמטיס ועבור לדף **ניהול משתמשים**. צור לפחות שני טכנאים בשם ובכתובת שתבחר; טכנאים מתחברים ב־`/mechanic/`.
5. תקלה מקומית ישנה מהמכשיר שבו נוצרה תיובא אוטומטית אחרי כניסת המטיס כתקלה לא משויכת. עבור ל**תקלות פתוחות** ושייך אותה לטכנאי כדי שתופיע אצלו. אל תמחק את נתוני אפליקציית המטיס לפני הייבוא.

**הסרת משתמש:** כפתור "מחק משתמש" מסיר אותו מרשימת הפעילים וחוסם את גישתו ב־Firestore. ההיסטוריה והמספרים הסידוריים שלו נשמרים, ואפשר לשחזר אותו מרשימת המשתמשים שהוסרו. לפני הסרה צריך לשייך מחדש תקלות פתוחות. ברשימת המשתמשים שהוסרו, כפתור "מחק סופית" קורא לפונקציית Firebase שמאמתת את המטיס ומוחקת את חשבון Firebase Authentication של המשתמש. רשומת זיהוי מינימלית נשמרת רק כדי לסנן היסטוריית תקלות; היא מוסתרת מרשימת המשתמשים. הפונקציה דורשת פריסה חד־פעמית כמתואר להלן. עצם יצירת חשבון Auth באמצעות ה־SDK היא ציבורית כשהספק Email/Password פעיל, אולם רק המטיס יכול ליצור עבורו מסמך הרשאת טכנאי ב־Firestore.

## פריסת שינויי Firebase

את האתר ב־GitHub Pages אפשר לפרסם בנפרד, אך מחיקה סופית והזרימה החדשה של החזרת דף, הגשה לבודק וסגירה דורשות פרסום הפונקציה וכללי Firestore החדשים בפרויקט `ezeizo`. ממחשב עם גישת מטיס לפרויקט, הרץ משורש ה־repo:

```sh
npm --prefix functions install
npx firebase-tools login
npx firebase-tools deploy --only functions,firestore:rules --project ezeizo
```

אפשר לפרסם את `firestore.rules` גם דרך Firebase Console → Firestore Database → Rules. אין לשמור פרטי התחברות או מפתח Admin ב־repo. לפריסת Cloud Functions ייתכן צורך בהפעלת חיוב בפרויקט Firebase.

ה־web API key בקוד מזהה את פרויקט Firebase ואינו סיסמה. המערכת היא המחשה עם נתונים מומצאים. אין להזין מידע מסווג או פרטים מבצעיים.

בגרסה 1.5.7 יומן פעילות מאפשר בחירה מרובה של טייסות ומטוסים מכל אחת מהן; יומן טייסת מאפשר טייסת אחת ובחירה מרובה של מטוסיה. שם קובץ של טופס בודד ובתוך ZIP הוא ״תקלה - מספר סידורי - תאריך פתיחה.pdf״ או ״הטענת מפתחות - מספר סידורי - תאריך פתיחה.pdf״.

בגרסה 1.5.9 היסטוריית מפתחות מציגה לכל מטוס תאריך וחודשים נפרדים לארז כחול ולשחק. כל סוג מתעדכן רק לפי הטפסים הסגורים שבהם סומן שבוצע בפועל; סוג שטרם הוטען מסומן בהתאם. ההיסטוריה מחושבת מטפסי ההטענה הסגורים, בלי כתיבה נוספת למסמך היסטוריה משותף, כך שהטענה של סוג אחד אינה משנה את האחר.
